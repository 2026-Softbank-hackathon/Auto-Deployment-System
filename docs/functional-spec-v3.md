**v3 변경 요약**: 아키텍처 v5.4.1 + 9/30 회의 의결사항 12개 + D-40~D-53 반영.

# 0. 개요

**한 줄 정의**: 로컬 웹앱을 올리면 AI 에이전트가 분석·수정하고, 온프레미스와 클라우드(AWS·GCP·Azure)에 운영 수준으로 원클릭 배포하는 시스템

**v3 변경**: 컨트롤 플레인 구조를 단일 프로세스로 갱신. P0/P1/P2 우선순위 체계 도입. 9/30 데모 포인트 반영.

**시스템 구성**

- 인터페이스: 웹 대시보드 (P0), CLI (P2), CI/Git 연동 (P2), AI 에이전트 (P1), MCP (P2)
- 컨트롤 플레인: API 서버 + 오케스트레이터 (단일 프로세스, TypeScript/Fastify), 통합 워커 (analyze/build/provision/verify 핸들러), Postgres 큐
- 데이터 플레인: 온프레미스(Intel Mac VM, Docker Compose, amd64), AWS ECS Fargate (P0), GCP Cloud Run (P2), Azure Container Apps (P2)

**용어**

- IR (앱 명세): 앱이 필요한 것을 클라우드 중립적으로 기술한 YAML 문서 (앱 요구사항만, 인프라 표현 없음)
- 프로필: 환경별로 미리 검증한 인프라 골격 + capabilities 선언 (`aws-ecs-basic`, `onprem-docker-basic` 등)
- 대상 환경 (Target): 앱이 배포될 곳 (온프레미스 VM, AWS 계정 등)
- 배포 (Deployment): 특정 버전의 앱을 특정 대상 환경에 올리는 1회 작업
- 통합 워커: job_type(analyze/build/provision/verify) 핸들러가 들어있는 단일 워커 프로세스 (v2의 "분석 워커", "빌드 워커" 등 분리 구조 대체)
- 환경 전환 (Switch): 동일 digest를 다른 환경(온프레미스 ↔ AWS)으로 라우팅하는 작업

**핵심 사용자 흐름**: 소스 업로드 → 스택 분석 · IR 생성 → (P1) AI 코드 수정 제안·승인 → IR 검증·프로필 대조 → 배포 대상 선택·승인 → 빌드 → 인프라 플랜·승인 → 프로비저닝 → 배포 → 검증 → URL 제공 → (P1) 환경 전환 데모

**우선순위 정의**

| 등급 | 의미 | 비고 |
| --- | --- | --- |
| P0 | 데모에 반드시 동작해야 함 | 10/1 20:00 목표 |
| P1 | 해커톤 제출에 포함 목표, DB·환경 전환 포함 | 10/3 10:00 목표 |
