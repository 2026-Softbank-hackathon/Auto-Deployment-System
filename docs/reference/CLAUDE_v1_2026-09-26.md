- 평가 대상은 배포 시스템 자체. 샘플 앱 품질은 평가하지 않는다.

## 3. 아키텍처 핵심 (docs/architecture.md, docs/diagrams/architecture_v3.png)
- **컨트롤 플레인 / 데이터 플레인 분리.** 데이터 플레인 = 온프레미스(Docker Compose·k3s, Linux·macOS·Windows VM), AWS, GCP, Azure
- **IR(앱 명세, YAML)** 중심: 모든 환경이 같은 IR을 입력으로 받고, 환경 차이는 **프로바이더 어댑터**가 흡수. 클라우드 고유 기능은 IR `overrides` + 어댑터
- 컴포넌트: API 서버(REST+SSE, 무상태) / 오케스트레이터(배포 상태 머신·환경 락, 활성 1대) / AI 에이전트(API를 도구로 호출하는 클라이언트) / 관측 게이트웨이(조회 대리, 무상태) / 추천·비용 엔진(규칙 계산, AI는 설명만) / 샌드박스 워커 풀(분석·빌드·프로비저닝·검증)
- 저장소: **Postgres(단일 진실 공급원 + 작업 큐)**, Redis(SSE 이벤트 스트림·캐시만), 오브젝트 스토리지(소스·로그·IaC state), 시크릿 볼트, 컨테이너 레지스트리
- 클라우드 연결: **역할 위임 + 단기 자격증명** (장기 키 저장 금지). 온프레미스: **에이전트 Pull(롱 폴링) + 1회용 등록 토큰**, 외부 노출은 Cloudflare Tunnel
- 관측: 앱에 OpenTelemetry 주입, 공통 태그(deployment.id, service.name, service.version, deployment.environment), 프로파일링은 전 환경 **Pyroscope**
- AWS는 App Runner 신규 가입 불가(2026-04-30~) → **ECS(Fargate/Express Mode)** 사용
- 메인 클라우드는 **GCP Cloud Run** 추천 (트래픽 분할로 카나리)

## 4. 설계 원칙 (코드 작성 시 지킬 것)
1. AI는 판단이 필요한 단계(분석·패치·진단·추천 설명)에만. 실행은 검증된 코드(IaC 템플릿). (NFR-08)
2. 코드 수정·인프라 변경·운영 롤백은 **사람 승인** 필수. 에이전트 도구의 `requires_approval`은 API 서버가 코드로 강제.
3. 컴포넌트 간 통신은 `packages/contracts`의 타입으로만. 서로의 내부 코드 import 금지.
4. **Postgres 테이블은 쓰기 소유 컴포넌트가 하나** (docs/erd/데이터사전_v2.md 참고). 다른 컴포넌트는 읽기만, 변경은 소유자에게 요청/이벤트.
5. 워커는 무상태·멱등. 작업에 job_id/attempt, 재시도+백오프, 데드레터.
6. 비밀값은 DB에 저장하지 않는다(볼트 참조만). 토큰은 해시만 저장. LLM 전송 전 비밀값 마스킹.
7. 모든 설계 결정은 대안과 이유를 `docs/decisions.md`(→ Notion ADR)에 기록. 팀 개발 20점의 근거.
