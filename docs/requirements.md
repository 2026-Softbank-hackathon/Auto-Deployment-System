# 요구사항 명세 (팀 합의본)

주제: 원터치로 하이퍼스케일러나 온프레미스 환경에 배포할 수 있는 AI 시스템
원칙: 공식 요구사항은 100% 충족 + 알파. 공식 "간단한 배포 예시"는 정답이 아닌 예시임에 유의.

## 1. 프로젝트 분석
- 소스를 올리면 기술 스택을 포함한 프로젝트 구조를 파악 (프레임워크, 언어, DB, 포트, 환경변수, 서비스 간 의존성)
- 지원 프레임워크: Rails 같은 올인원, Express·Hono 같은 경량, SPA, Next.js, 기타(Spring 등)

## 2. AI 코드 자동 수정
- 배포에 필요한 코드 변경을 AI가 수행 (SQLite → Postgres, 설정 환경변수 분리, 헬스체크 추가, Dockerfile 생성)
- 변경은 diff로 확인·승인
- AI 에이전트 형태로 분석 → 계획 → 코드 수정 → 배포 → 검증

## 3. 배포 환경 선택 및 추천
- 배포 환경 선택, 트레이드오프(비용·성능·확장성) 기반 자동 추천·적용, 사용자 커스텀
- 배포 형태: 함수형 서버리스(Lambda, Cloud Functions), 컨테이너(Fargate, Cloud Run), 인스턴스(EC2, GCE)

## 4. 데이터 관리
- 환경변수·보안 키 관리, DB 관리 (클라우드·로컬 모두)

## 5. CI/CD 연동
- 로컬·클라우드 모두, 커스텀 가능

## 6. 멀티 환경 배포
- 같은 앱을 여러 환경에: 최소 온프레미스 1 + 클라우드 1, 가능하면 클라우드 2 이상
- 환경 변화에 강함(Docker처럼), 클라우드·온프레미스 차이를 시스템이 흡수
- 클라우드별 고유 기능 대응 (예: Cloud Run 트래픽 분할 카나리, 관리형 DB·시크릿·로깅)
- 공통 추상화와 고유 기능 사이 균형을 설계에 반영
- 누구나 접근 가능한 URL (온프레미스는 터널링)

## 7. DB 마이그레이션
- RDBMS 마이그레이션 용이, 로컬 DB → 클라우드 관리형 DB 전환 포함

## 8. 애플리케이션 아키텍처 범위
- MSA·모놀리스 등 넓은 범위를 클라우드·온프레미스 모두에, 대규모 가용성 검토

## 9. 운영 수준 인프라 자동 구성
- 관리형 DB, 인증서, 서브넷 등 네트워크, 기타 운영 필수 설정
- 모니터링 + 시각화 자동 구성: 메트릭, 로그, 트레이스, 프로파일링

## 10. 배포 로깅
- 배포 작업 로그 기록·저장, 누가·언제·어떤 버전·어디에 배포했는지 이력

## 11. 배포 전략
- 롤백, 블루그린, 카나리, 롤링

## 12. 배포 실패 대응
- AI가 로그 분석·원인 진단 → 수정 후 재시도 또는 롤백

## 13. 비용 효율성 (AI ROI)
- AI 토큰 비용 대비 ROI (비즈니스 어필, 중요), AI는 필요한 곳에만, 효과 수치화, 인프라 예상 비용

## 14. 동시 배포 안전성
- 여러 명이 동시에 배포해도 충돌 없음 (배포 락, 인프라 상태 공유)

## 15. 다중 클라이언트 지원
- 여러 클라이언트 지원, 높은 동시 처리 가용성

## 16. 배포 대상 환경
- 클라우드: GCP, AWS, Azure / 온프레미스: 리눅스·맥·윈도우 VM

## 17. 샘플 애플리케이션
- 평가 대상 아님. 모놀리스 1, MSA 1, OS별 가능. 로컬에서 동작. 개발 시간은 배포 시스템에 집중
